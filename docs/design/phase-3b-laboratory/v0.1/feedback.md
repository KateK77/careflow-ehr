# Design feedback and approval boundary v0.1

This is a **proposal**; the phase name and implementation scope are **not approved**. The user authorized review of the existing project, preparation of requirements/architecture and publication of an unmerged documentation PR. The [original prompt](prompt.md) is preserved verbatim.

No new lab functionality, model migration, staff group, catalog seed, manual acceptance result or approval to implement has been supplied. Prior approved phase names, clinical behavior, requirements, Chinese sources, English translations and historical records remain unchanged.

Recommendations are intentionally concrete for review: one panel/order in an owned in-progress encounter, explicit lab assignment, separate late-result permissions, one active specimen, typed report snapshots, immutable publication/corrections and exact-revision acknowledgement. The [open questions](README.md) identify review choices, especially Lab Staff naming versus original LabTech terminology, staffing/finalization separation, reviewer coverage, specimen/cancellation limits, report storage and withdrawal policy. They are not silent changes to approved requirements.

Existing deferred UX improvements remain deferred. New lab pages are designed to reuse readable errors/navigation/audit conventions without modifying current application screens. Stop after design publication and verification; merging this design PR or implementing any proposed feature needs further approval.
