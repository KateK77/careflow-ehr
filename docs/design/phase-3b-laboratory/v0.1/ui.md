# Page and interaction proposal v0.1

**Design proposal; implementation and phase name are not approved.** These are future server-rendered Django pages, not existing routes or implemented controls. Keep CareFlow's original design, top bar/sidebar, visible staff identity/role, patient banner, clear actions/messages, DEMO notice and responsive contained tables. No Epic assets, React rewrite or cosmetic-only placeholder functionality.

## Proposed pages

| Page / illustrative route | Role / content / actions |
| --- | --- |
| Catalog `/app/lab/catalog/` | Physician sees active synthetic panels; Administrator has explicit versioned create/activate/deactivate actions. Label mock units/bounds as demonstration input rules. No delete. |
| Encounter ordering `/app/patients/<id>/encounters/<id>/lab-orders/new/` | Assigned Physician, in-progress encounter. Show fixed patient MRN/name/encounter/physician, panel and specimen definition. Save draft → reopen/edit → Review order → Confirm submission. Warn on intentional repeat testing and preserve input. |
| Order detail `/app/lab/orders/<uuid>/` | Scoped full or restricted requisition rendering. Show independent order/specimen/result/review badges, frozen ordered context, live patient identity differences, actors/times/versions, appropriate cancel/collect/receive/result actions and history. Do not use full chart context for standalone Lab Staff. |
| Patient laboratory history `/app/patients/<id>/lab-history/` | Authorized chart readers. Filter panel/date/order/publication/review state; show current published results with revision and superseded-history access. Draft visibility follows matrix. Link only authorized encounters; display completed-encounter/pending-result combinations. |
| Nursing collection `/app/lab/collection/` | Nurse operational queue of submitted orders awaiting collection/recollection. Show patient identity, encounter state and specimen attempt. Confirm identity/collection time/type; correct only before receipt; no encounter/readiness transition. Link from Nursing workspace as a separate lab task, not an edit to rooming/vitals. |
| Laboratory workspace `/app/lab/workspace/` | Lab Staff minimal unassigned queue and My assigned orders tabs; status/panel/time filters. Claim unassigned order explicitly. Restricted queue omits unrelated patient detail; after claim show minimal requisition, accession confirmation, Receive or Reject specimen, Enter results. Administrator assignment view is explicit and separate from result entry. |
| Result draft `/app/lab/orders/<uuid>/results/<revision>/edit/` | Assigned Lab Staff. Catalog-generated typed numeric/unit or coded fields, explicit not-performed reasons, performed time when applicable, draft status and Save draft. Preview final report then Confirm finalization with scope/version warnings. No silent auto-publish. |
| Result detail/history `/app/lab/orders/<uuid>/results/<revision>/` | Authorized readers see publication status, revision, source/specimen, values+units or absent reasons, entry/finalizer identities, timestamps and correction reason. Full text remains accessible. Draft clearly marked Unpublished to permitted Lab/Admin readers only. Correct result creates a new draft; show previous/current comparison without changing original report. |
| Physician review `/app/lab/review/` | Ordering Physician's current published/unreviewed results, including completed encounters; filters panel/date/current revision. Open full report → explicit Acknowledge this revision. Show exact revision/time and stale-correction conflicts. Revisit prior acknowledgements in history. This is a lab review list, not a generic Inbox or clinical alert monitor. |
| Patient chart/encounter summaries | Small scoped lab panel with counts and latest current published rows; pending collections/results/unreviewed counts remain distinct. Link history, owned order composer when allowed, report revision and acknowledgement. Never synthesize results into signed SOAP or add hidden clinical recommendations. |

## Readable states and feedback

Use labels such as Submitted / Specimen collected / Awaiting publication / Unreviewed, never a single ambiguous Complete badge. Always pair values with unit and report revision. If a report is corrected, show Corrected report — review required; the prior report shows Superseded with its original acknowledgement. If only a correction draft exists, continue showing the previous report as current and hide draft values from clinical readers.

Preserve failed input, highlight fields and render non-field errors as plain messages. Do not show internal `__all__`, DB constraint names, technical exception text or internal IDs as the only clinical labels. Display human identifiers together with stable public order/accession references, actor names and explicit clinic-local timestamps. New lab forms should render each error once; this does not implement the separate deferred fix in existing allergy forms.

Responsive design uses grouped columns, readable minimum widths and visible conditional horizontal-scroll/keyboard hints. Never ellipsize result values, units, patient identity or correction reasons without a full accessible equivalent. Compare screens at desktop, split-screen and narrow mobile widths; do not infer universal usability from one width. Empty states distinguish no orders, no collected specimen, unpublished results, not-performed analytes and no acknowledgement.

## Completed encounter scenario

An order is submitted during the in-progress encounter, then the existing SOAP note is signed and the encounter completed while the lab is pending. Nurse collection and assigned Lab Staff processing continue through lab-specific screens. The report publishes and appears in the ordering physician's unreviewed list and authorized patient/encounter summaries. Physician acknowledges the exact report revision. A later correction appears unreviewed again. Throughout this sequence the encounter remains completed, check-in provenance unchanged, and signed SOAP content/version/signature untouched. If the ordering physician is inactive, display unresolved responsibility and retain the item; do not silently redirect acknowledgement to an Administrator.
