# CareFlow EHR — Standalone Version Descriptions

These are complete, independently readable English product requirements. Each describes the entire product for its generation: purpose, roles, pages, workflows, data rules, architecture, UX, acceptance criteria, operation and limitations. They are not concatenated chat messages, feedback lists or old prompts.

| Generation | Complete description | Final scope |
| --- | --- | --- |
| v1.0 | [Integrated EHR requirements](v1.0.md) | Phases 0–8: patient, clinical, nursing, diagnostic, medication, portal, financial and hospital workflows |
| v2.0 | [Complete website and EHR requirements](v2.0.md) | Full EHR, unified entry, responsive staff/patient workspaces and clear registration/booking forms; provisioned accounts |
| v3.0 | [Complete blue-interface and registration requirements](v3.0.md) | Full EHR, blue identity, username/password/confirmation signup, new patient charts, staff approval and separate hosted configuration |

**Choose one description; do not concatenate the versions.** The full shared product requirements deliberately appear in each file. Optional provenance links at the end support auditability; they are not prerequisites for understanding the functional brief.

## Version meaning

- v1.0 describes the integrated product, not every unimplemented ambition in the original specification.
- v2.0 and v3.0 identify website generations; these names do not assert new release tags or merges of the open application stack.
- The historical v3 prompt revision 3.1 is the final no-email requirements revision of the v3 website, not a fourth website generation.
- Each consolidated document is revision 1.0, dated November 16, 2026.
- Requirements and historical verification results are separate. No past test count is presented as a new run.
- Visitor sandboxes and automatic demo resets remain separate proposals, not delivered capabilities.

Original Chinese requirements, English translations, prompts, feedback and test evidence remain intact. Superseded email requirements do not appear as active v3 requirements.
